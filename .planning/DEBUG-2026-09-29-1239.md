# Debug Report - 2026-09-29 12:39 UTC

**Symptom:** RAFA chat returns an API key error and dashboard navigation feels very slow.
**Mode:** performance
**Tool calls used:** 8/10

## Investigation
- Checked the OpenRouter key using the account key endpoint; the configured key is still invalid.
- Timed authenticated dashboard endpoints. Company and Settings returned in 2-40 ms; Leads and Bookings took about 0.5 s; Overview took about 1 s when warm.
- Inspected Supabase Edge Function logs. The deployed version 3 `contacts?includeHistory=true` request took 8.784 s.
- Read the deployed Edge Function source and found `listUsers` issuing a separate history query for every contact.

## Root Cause
`supabase/functions/rafa-agent-api/index.ts` - `listUsers` performed N+1 conversation-history queries, causing cold dashboard page loads to wait for many database requests. The expired `OPENROUTER_API_KEY` independently prevents RAFA chat from receiving model replies.

## Fix Applied
- Replaced per-contact history queries with batched, paginated queries grouped by user.
- Added a 12-second GET cache and in-flight request sharing in the dashboard API client.
- Deployed `rafa-agent-api` version 4.
- Verification: dashboard build passed; authenticated Overview returned HTTP 200 in 956 ms; Supabase logs show version 4 contacts request at 410 ms, down from 8.784 s.
- Verification: OpenRouter key check still reports invalid. A fresh model reply cannot be verified until a valid key is configured.

## Related Observations
- Security and performance advisors reported no critical findings related to this fix.
- Free Nemotron's data terms still preclude personal or confidential data.
