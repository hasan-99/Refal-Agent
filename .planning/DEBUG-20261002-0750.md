# Arabic WhatsApp conversation debug

Date: 2026-10-02

## Root causes

- Identity questions had no deterministic REFAL identity route and fell through to retrieval, where no approved knowledge existed.
- Arabic appointment words were treated as booking intent without respecting a negative/deferral, and unfinished booking state could intercept a new topic.
- Name extraction accepted the entire message when no explicit name cue existed.
- Cyprus project enquiries had no useful intent path and reached a generic fallback.
- Price/fee queries were classified as objections. Broad `registration` safeguards then rejected ordinary company-formation service prices as if they were legal-status claims.
- The connected knowledge source/document/chunk tables were empty. Embedding search therefore had nothing approved to return.
- The WhatsApp handler prepared inbound state and then repeated preparation in the router. A cold local embedding-model load added about 2s to first-use latency. The model also spent a small completion cap on hidden reasoning and sometimes returned no customer-facing text.

## Changes

- Route identity and vague-project requests appropriately; extract names only with an explicit introduction; respect booking deferrals and new topics during unfinished bookings.
- Keep a neutral price query informational. Safety rules now distinguish approved service-package prices from claims about legal status, returns, or outcomes.
- Reuse inbound classification/state, warm embeddings on worker startup, and limit provider fallback to transient errors.
- Bound reasoning/output for short grounded chat and reject unfinished or empty model responses.
- Seeded the live Supabase knowledge tables with approved, three-language REFALCO overview content and a separate owner-authorized LAMAR price entry, indexed six chunks, and backfilled embeddings. LAMAR is explicitly attributed; its relationship to REFALCO is not verified.
- Aligned WhatsApp, dashboard, and Edge Function instructions and price/status validation.
- Added live knowledge and WhatsApp-core conversation evaluators plus Arabic, English, Greek, name-capture, booking, and pricing regression coverage.

## Verification

- `npm test`: 88 passed, 0 failed.
- `npm run eval:knowledge`: 14 passed, 0 failed; approved Arabic, English, and Greek retrieval all passed.
- `npm run eval:conversation`: five live tests passed against the real Supabase retrieval and OpenRouter model path, including an Arabic no-meeting services question, an Arabic company-formation price query, English, and Greek language switching. The service/no-meeting case captured no name, created no booking, and created no handover.
- Warm-request average across four requests: route 5 ms, booking gate 1 ms, embedding 5 ms, Supabase retrieval 669 ms, model 815 ms, end-to-end 1.50 s. Cold first request: 4.58 s, of which embedding initialization was 1.85 s. The worker already warms embeddings in the background.
- Prior stage-only sample: embedding 249 ms and retrieval 724 ms average across 10 queries; latest post-change knowledge evaluation measured 216 ms and 644 ms across 9 queries. These are not a strict same-query comparison. No valid full-request before measurement exists because stage instrumentation was not present then.

## Remaining limitations

- The REFALCO public pages reviewed contain no company-formation price. The €999 + VAT one-time package and included services are stated only as published by LAMAR; the current applicability and corporate relationship need human confirmation. Legal/tax outcomes, guarantees, and delivery estimates were intentionally not imported.
- A model/RAG WhatsApp-core path test was run without sending a customer WhatsApp. The currently running standalone WhatsApp worker was not restarted: disconnecting it could interrupt live chats or scheduled notifications. It must be restarted during a safe window before the running process loads the code changes; a live transport delivery also needs an opted-in QA WhatsApp recipient.
- The repository was already broadly dirty before this work. No commit was made to avoid capturing unrelated changes.
