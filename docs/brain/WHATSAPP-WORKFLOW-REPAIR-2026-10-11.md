## Proven defects and changes

* `messageRouter.js` and `intent.js` previously classified phrases before generation; greeting, identity, language and service shortcuts could swallow substantive requests. The active WhatsApp composition now uses structured contextual model classification. Fixed greetings, fixed service lists, objection answers, language acknowledgments and post-model sales/jurisdiction rewrites were removed from the active answer path. Identity comes from the validated profile. Remaining compatibility code must be reviewed after real replacement verification before declaring this goal complete.
* `claimPolicy.js`/`refalcoAnswer.js` exact token/entity overlap rejected dialect and translations and could confuse uncertainty with a business claim. Some rejected overview additions really lacked service evidence; they were not assumed to be false positives. `semanticGrounding.js` reviews exact claims, actor, negation, conditions, package relations and language. Deterministic privacy, unsupported guarantees, personalized conclusions and unconfirmed action restrictions remain first.
* `agentTools.js` previously gave colloquial and contextual query results equal votes. Irrelevant salary/dividend, residence and trademark results occupied the finite evidence window before overview material. Contextual relevance selection now ranks authorized sections; `agentLoop.js` retains an immutable candidate pool so later stronger sections replace weak early ones. New candidates, duplicates and omitted sections are distinguished. Complete sections are retained or omitted; conditions are never cut to fit.
* The newly expanded prompt itself caused a reproduced `PROMPT_TOKEN_CEILING_EXCEEDED` failure. The decision contract was compacted without increasing the limit. Accumulated evidence is budgeted against the actual UTF-8 prompt, history, rejection feedback and schema reserve, and passed consistently to generation and validation.
* Edge sanitization treated `validationReasons` as UUID identifiers and lost reason codes. `agentTracePrivacy.js` and its generated Edge mirror now share one safe contract. Worker measurements retain evidence counts/IDs, outcomes and timings. Events retain both flattened compatibility fields and authoritative `event.fields`. Trace and persisted source-turn IDs correlate steps. Enrolled controlled tests can store redacted rejected drafts and exact evidence through a separate administrator diagnostics endpoint; ordinary activity excludes these inspection records.
* `messageRouter.recordHistory` lost its nonenumerable qualification-evidence symbol during adapter spreads, and omitted `scorerVersion`/`evidenceFingerprint` from lead-score writes. This caused the workflow-persistence warnings. The symbol survives intermediate spreads and is removed before JSON persistence; required scorer fields are retained. Workflow writes use named independent outcomes so one failure does not hide other successful writes. Edge intent validation now accepts the full contextual taxonomy.
* Search and expansion enforce the same source approval, current revision, expiry, mutable-price validity and whole-section explicit fact blocks. The migration asserts the expected live catalog predicates before replacing them and discounts incidental alias discovery scores.
